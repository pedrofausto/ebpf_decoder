# Release Readiness: JSON Decoder Security Hardening

## Overview
The `ebpf-json-decoder` has been hardened against malicious JSON payloads and common denial-of-service vectors. This audit confirms the implementation of strict boundaries and successful verification against adversarial inputs.

## Security Controls
- **Payload Size Limits**: `MAX_EVENT_PAYLOAD_SIZE` caps event payload handling at 1MB, and `parsers/json.rs::MAX_JSON_SIZE` caps JSON parser input at 1MB.
- **Recursion Limits**: Leveraging `serde-json` default recursion limit of 128, which is safe for the restricted payload size.
- **Backend Safety**: Both `simd-json` and `serde-json` backends are configured to fail gracefully on malformed or non-UTF8 data.
- **Resource Exhaustion**: Shared buffers for `simd-json` are pre-allocated and cleared after use to prevent memory leaks or fragmentation.

## Verification Results
All security-focused tests passed successfully:

## Maintenance Recommendations
- **Fuzzing**: Consider integrating `cargo-fuzz` for continuous verification of the parser backends.
- **Logging**: Security-related failures are logged at the `debug` level to prevent IO-based DOS but allow for forensic analysis.
- **Mismatch Policy**: For configured `check` and `decode`, bounded kernel guards drop packets that clearly do not match the expected format before userspace parsing.
